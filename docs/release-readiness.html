04Changes by repository

This inventory describes the release-candidate checkout, including pre-existing local project work being brought into version control. It does not imply that every newly tracked file was authored during the audit.

Android worker hench
  • NWC client authentication: validate the response's recomputed event ID, BIP-340 signature, expected wallet author, recipient, and request correlation before trusting or decrypting it.
  • NWC interoperability: emit the standard unescaped Base64 IV rather than a URL-encoded IV. The previous encoder failed against the independent wallet fixture. Keep a deterministic external-implementation test vector.
  • NWC server replay protection: canonical lowercase event IDs and persistent request-ledger handling prevent case variants and redelivery from becoming another spend.
  • Wallet correctness: retain real payment preimages, page invoice lookup beyond the newest result window, and start the NWC server only after explicit pairing. These are source/regression checks, not a real-money settlement claim.
  • Payment lifecycle: encode compound idempotency identities as JSON to prevent delimiter collisions, broaden in-flight deduplication, bound unpaid admission, retain paid/replay-sensitive records, and catch settlement at the polling deadline. Preserve monotonic payment states.
  • Remote browser isolation: separate remote-rendering state from operator login cookies and fail closed when the isolation feature is unsupported. Block disallowed main-frame, subframe, subresource, and redirect destinations; treat selector input as data instead of JavaScript source.
  • Blossom and URL handling: validate upload result URLs and redirect behavior; strengthen download URL/DNS safety boundaries.
  • Runtime/package updates: track component install success independently so a successful curl install cannot mark a failed yt-dlp update complete. Replace the old Python byte-patching workaround, choose QuickJS explicitly, use adaptive video/audio merging, and return the proper MKV media type.
  • Script/package and application lifecycle work: enforce canonical ZIP destination containment, correctly JSON-encode uploaded-file metadata, keep the debug restore activity non-exported, and update foreground-service startup. Remove obsolete onboarding/contract scaffolding and unused health-check code.
  • Release-only JNI failures: preserve JNA native dispatch fields and generated structure/library names through R8. Scope the absent AWT API exclusion to JNA's desktop-only helpers. Verify the actual minified wallet rather than relying on debug builds.
  • Protocol notification handling: accept the initialized notification without incorrectly trying to send a JSON-RPC response to it.
  • Credential hygiene: replace exposed recovery-material fixtures with synthetic vectors, keep build credentials excluded from Git, and warn that deletion from current files does not revoke previously exposed material.
  • Build and documentation: update Android tooling and native/JVM dependencies, include reproducible build inputs and patches, retain third-party license notices, and document runtime/ABI limitations.
Rust worker and dashboard hench-cli
  • Make the project a standalone checkout with its own manifest, lockfile, source, and vendored ContextVM SDK rather than relying on an unavailable neighboring SDK layout.
  • Authenticate NWC replies and bind settlement to the expected request/invoice instead of accepting attacker-signed or unrelated responses.
  • Persist the canonical job record before issuing an invoice, using private-at-creation files and atomic/fsynced writes. Refuse payment initiation when durable storage fails.
  • Keep paid replay history under unpaid request churn; reject interrupted or busy jobs rather than billing the same canonical invocation again.
  • Return correlated, sanitized payment-initiation errors in the shared SDK. Preserve detailed diagnostics in server logs and keep pre-invoice retry behavior.
  • Render job fields as text, protect administration from hostile origins and DNS rebinding, and require authentication when exposing the dashboard beyond loopback.
  • Fix dashboard name/form state and initial-fetch recovery so polling continues after a transient error and does not erase unsaved edits.
  • Drain the downloader's stderr pipe throughout execution while retaining only its final bounded error tail. The former early cutoff could break a verbose child process with SIGPIPE.
  • Update dependency pins, build documentation, and the project's own MIT license while preserving the SDK's upstream license.
Static browser client hench-web
  • Verify discovery and worker events cryptographically; enforce announcement freshness and reject forged or mismatched authors.
  • Correlate replies, progress, and payment messages to the outstanding signed request event and its JSON-RPC ID. An authentic old invoice/result cannot attach to a new invocation.
  • Keep client identity stable when local storage is available so completed canonical calls can use the worker's replay protection.
  • Make JSON overrides replace schema-form arguments without native required-field validation blocking dispatch.
  • Hide invoice controls on terminal success/failure and preserve the actual job result/status flow.
  • Vendor the browser's crypto/QR dependencies with source pins, hashes, and licenses instead of runtime CDN imports. Share wire/trust/correlation checks with the nsite demo.
Nostr site publisher and host hench-nsite
  • Verify manifest signatures and exact requested author, identifier, or snapshot ID; verify served blob bytes against the manifest digest.
  • Use canonical subdomain origins for public tenants. Shared-origin path-prefix routing requires explicit development mode; loopback binding is not treated as proof that a request is private.
  • Validate publisher-selected servers, BUD-03 locations, redirects, and resolved destination addresses at connection time. Keep the operator-configured fallback as a separate trusted setting.
  • Derive content type from authenticated path information rather than letting an untrusted blob host turn text into executable HTML.
  • Bound blob bytes, concurrent fetches, request URL size, relay messages, and fetch duration. Cache only immutable snapshots immutably.
  • Exclude hidden directories/files from publication, reject unsafe filenames and symlinks, and refuse public publishing with the built-in test key.
  • Make the local integration script use its own local key/services, handle occupied default ports, exercise root/named/snapshot routing, and clean up after itself.
  • Bring the demo's browser dependencies, replay defenses, argument overrides, and invoice cleanup in line with the standalone web client.

Expat: not a demonstrated Hench exploit

CVE-2025-66382 is an upstream CPU-denial-of-service issue. The maintainer reports that a crafted roughly 2 MiB XML file can take 25–100 seconds to process. The issue remained open without a published fix at the time of review, and the reproducer was not public.

Hench does not offer an XML-parsing job. However, the bundled yt-dlp imports xml.etree.ElementTree and calls _download_xml for manifests. That makes “no XML job” different from “no XML parser can ever be reached.” The specific vulnerable parsing path and a working attack through Hench were not established. Treat this as a residual dependency advisory, not as proof of a remotely exploitable Hench vulnerability or a standalone reason to block publication.

Job subprocess deadlines bound execution time but do not prevent CPU consumption before termination. The published impact is DoS, not reported code execution or wallet theft.

Native advisories that were not silently ignored

  • Spark full lockfile: hickory-proto 0.25.2 (RUSTSEC-2026-0118/0119) and tokio-tar 0.3.1 (RUSTSEC-2025-0111) remain in non-shipped workspace/dev paths. They were absent from the selected Android normal/build graphs for both ABIs. Maintenance warnings remain for rustls-pemfile, paste, and proc-macro-error2.
  • curl's nghttp2: CVE-2026-27135 requires extension-receive options not enabled by this integration. The impersonation fork retains its older priority API dependency.
  • curl's ngtcp2: CVE-2026-40170 requires qlog, which the selected curl library path leaves off.
  • TLS/backend applicability: the GnuTLS-only CVE-2026-107928 does not apply to this BoringSSL build. CVE-2026-86411 is already addressed by the curl 8.22.0 baseline. BoringSSL has no conventional release/CVE feed, so no universal “advisory-free” claim is made.

07Limits and operator actions

Before handling real value

  1. Retire exposed credentials wherever used. Move any affected funds to a fresh, privately generated seed and replace identities derived from exposed material. Rotation was not performed by the audit and must not be inferred from fixture cleanup.
  2. Confirm a small, authorized real-money workflow. Invoice creation, actual settlement, result delivery, accounting, and spending/refund expectations need operator validation with the chosen production wallet. This audit moved no funds.
  3. Review crash-window expectations. The CLI refuses a second charge after interrupted jobs, but a crash between invoice issuance and settlement recording can leave a paid-but-unrecorded invoice requiring operator reconciliation.

Before distributing or deploying

  1. Build/sign the production artifact with release credentials. The tested installs were isolated QA packages; no store submission, upgrade of the original wallet-bearing app, or production signing check occurred.
  2. Use an appropriate production Breez API key. The developer key file is ignored by Git, but its value is intentionally embedded in a built APK; APK distribution does not keep that key secret.
  3. Deploy/restart the existing nsite service to load the patched host. Pushing source does not update a running process. Review public bind/proxy/origin configuration and leave development tenant routing disabled.
  4. Provide required GPL corresponding source and build inputs for bundled components. MIT applies to Hench's own code; it does not erase third-party obligations. License notices alone are not a legal compliance certification.

Not exercised

  • x86_64 hardware or emulator execution; x86_64 was built and structurally checked.
  • Every supported website, cookie-authenticated extractor, device model, Android version, or network failure mode.
  • A separate final paid screenshot job or complete user-installed-script import-to-execution journey. Related code/regressions were reviewed; they are not claimed as live end-to-end passes.
  • Real Lightning spending/settlement, funded wallet recovery, or production credentials.
  • Sustained public-load/DoS testing, long soak tests, or a formal accessibility certification.
  • An Expat exploit against Hench, or a private upstream reproducer.

Known operational limits

  • CLI media URL checks occur before the downloader runs; hostile DNS rebinding during the external fetch is not claimed to be prevented.
  • Android WebView checks are not a claim of complete DNS-rebinding or browser-channel isolation. Secondary URLs fetched internally by yt-dlp are not all filtered by the initial URL check.
  • Nsite buffers each blob up to its configured limit; it is not an unbounded streaming CDN.
  • Installed script tools execute with app access and must be treated as trusted software.
  • Dependency results are a dated snapshot, not a guarantee against future disclosures.
